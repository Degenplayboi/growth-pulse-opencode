# Growth Pulse Business

Internal business operating capability. This skill THINKS and ORGANIZES; it does
not replace delivery skills. Delivery stays with frontend-design, design-system,
react-next, and quality/deploy skills. Evidence claims follow
`growth-pulse-verification`; fact labels follow `growth-pulse-research`.

## When to use

- Business strategy, prioritization, decision support, planning
- Operations: processes, SOPs, bottlenecks, automation opportunities
- Project management: requirements, milestones, dependencies, deliverables
- Marketing strategy, positioning, campaigns, offer analysis
- Sales pipeline, qualification, website auditing, opportunity identification
- Any client project framing (scope, acceptance criteria, handoff)

Do NOT invoke for pure code/design tasks. DO invoke to frame them.

## Internal vs client (load-bearing)

- INTERNAL capabilities (lead gen, outreach systems, marketing automation,
  social automation, BI) are NEVER automatically client-facing services.
- Services come ONLY from `docs/business/services.md` + explicit user decisions.
- Never invent a service catalogue, pricing, or client commitments.

## Method

1. EXECUTIVE: restate goal, priorities, constraints; decision support with
   options + trade-offs + PROPOSED recommendation (never present as fact).
2. OPERATIONS: current process → bottleneck → automation or SOP proposal;
   smallest change that removes the bottleneck.
3. PROJECT: requirements → scope → acceptance criteria → milestones →
   dependencies → deliverables. Every criterion testable.
4. SALES: discovery → qualification → website audit (actual observations only)
   → opportunity → relevant service (must exist in services.md) → next action.
5. CLIENT DELIVERY: REQUEST → REQUIREMENTS → SCOPE → ACCEPTANCE CRITERIA →
   PLAN → DESIGN → BUILD → TEST → AUDIT → FIX → RETEST → PRODUCTION VERIFY →
   HANDOFF. Verify acceptance criteria, not just "it builds".

## Rules

- Never invent names, emails, problems, budgets, relationships, interactions,
  intentions, tech stacks, results, or testimonials. Missing info = UNKNOWN
  or `[TODO: ...]`, never filled in.
- Business quality gate: does this acquire/convert/deliver/retain customers,
  reduce effort or cost, or improve quality/reliability/knowledge? If not,
  say so and question the work.
- Persist what matters to `docs/` (decisions with dates, pipeline state,
  requirements). Memory is not storage.
- Consequential actions (contracts, commitments, billing, external sends,
  spend) require human approval — prepare, don't execute.

## Output

- Goal restatement + classification (internal vs client) + plan or artefact
  (scope table, SOP, pipeline update) + file paths written + approval items
  (if any) + Not verified items.
